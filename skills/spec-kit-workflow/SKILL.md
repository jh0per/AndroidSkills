# Spec Kit workflow for Android and KMP

Spec Kit turns `spec-driven-development` into agent commands with files on disk. Its defaults are
written for web and backend projects: tests are optional, paths are `src/` and `tests/`, and the
plan's mobile option is a placeholder. This skill makes it fit a Gradle project. The method
(what a good spec and plan contain) lives in `spec-driven-development`; the test loop inside each
task lives in `android-tdd`.

## Prerequisites

- **Check the installed version first.** The CLI moves fast; command spelling, flags and file
  names below match the 2026 releases. Run `specify version` (or `specify self check`) and, if
  anything here disagrees with the project's installed files, the installed files win.
- Python 3.11+ and `uv`. Install the CLI with `uv tool install specify-cli`; upgrade with
  `specify self upgrade`, then `specify integration upgrade <key>` in the project.
- **Command spelling depends on the agent.** The references write `/speckit.plan`. Claude Code
  skills mode uses `/speckit-plan`; Codex uses `$speckit-plan`. Look in `.claude/skills/` or
  `.agents/skills/` for the installed `speckit-*` folders and use that form.
- The steps run **inside the agent chat**, not in a terminal. Only `specify ...` is a shell command.

## Steps

### 1. Adopt in an existing Android repo

```bash
git switch -c spec-kit-adoption            # reviewable baseline; commit or stash first
specify init --here --force --integration claude --integration-options="--no-model-invocation"
# Codex instead:  specify init --here --force --integration codex
specify extension add git                  # optional: numbered feature branches (001-short-name)
git status && git diff --stat              # read what was added before committing
```

- `--force` only allows init in a non-empty directory; it can replace files at managed paths, so
  run it on a clean tree and review the diff.
- `--no-model-invocation` (Claude) keeps the `speckit-*` skill descriptions out of context, so they
  do not crowd out the project's own skills; they run only when typed.
- Commit `.specify/` (constitution, templates, scripts) and the integration's skill folder so the
  whole team gets the same commands. Add `specs/` to version control; it is the feature history.
- Monorepo with several apps: one `.specify/` per app directory, not one at the root.

### 2. Constitution: rules that are already true

Run `/speckit.constitution` once, with the principles taken from the repo's README, `CLAUDE.md`,
convention plugins and CI, not invented. Start from `references/constitution-android.md` and delete
what the project does not do. It lands in `.specify/memory/constitution.md`; every plan is checked
against it.

The one principle to keep in every Android constitution: **Test-First (NON-NEGOTIABLE)**. Spec Kit's
tasks template treats tests as optional unless the spec or constitution asks for them; without this
line `tasks.md` has no test tasks at all.

### 3. Override templates once, for Gradle

Put project-local copies in `.specify/templates/overrides/` (same file names as in
`.specify/templates/`; overrides win over presets, extensions and core):

- `plan-template.md`: replace the source-tree options with the module/source-set layout and fill the
  technical context defaults. See `references/android-templates.md`.
- `tasks-template.md`: Android path conventions, test tasks mandatory and placed before the code
  they cover, and a last task that runs the project's single gate (`./gradlew verify`, see
  `gradle-quality-gate`).

Commands are materialised into the agent's folder at install time; templates are resolved when a
command runs. After editing an override, run one `/speckit.plan` on a throwaway feature to see that
it is picked up.

### 4. Per feature

```text
/speckit.specify Show the user's orders on a new Orders screen, available offline with the last
loaded list. Pull to refresh. Guests see a sign-in prompt instead.

/speckit.clarify Focus on offline behaviour, process death and what guests see.

/speckit.plan Kotlin 2.x, KMP targets android + iosArm64 + iosSimulatorArm64. New module
:feature:orders using the existing convention plugin. MVI on AndroidX ViewModel with Koin, Navigation
Compose (see compose-mvi-viewmodel). Ktor client from :core:network, cache in Room KMP in :core:data.
Tests: commonTest with fakes and Turbine, Compose UI tests via runComposeUiTest for the stateless Ui.
No new dependencies.

/speckit.checklist Focus on Android edge cases: rotation, process death, offline, permissions,
accessibility, locales.

/speckit.tasks Tests first for every acceptance scenario; one phase per user story; exact module
and source-set paths; last task runs ./gradlew verify.

/speckit.analyze

/speckit.implement Only Setup and Foundational phases. Stop before user stories.
/speckit.implement Now US1 only. Run the module's tests after each task.
/speckit.converge
```

- **Specify** gets the what and why only. If you catch yourself typing "ViewModel" or "Room" in
  `/speckit.specify`, move it to `/speckit.plan`.
- **Clarify** asks up to five questions per run; run it again with another focus rather than
  answering in the plan. Walk the Android edge-case table from `spec-driven-development`.
- **Plan** arguments carry the stack and constraints; name the existing modules and skills to reuse.
  Read `plan.md`'s Constitution Check: a violation must be justified in Complexity Tracking or
  fixed, not ignored. Read `research.md` for library choices the agent made silently.
- **Checklist** items are reviewer-owned: a human ticks them. `/speckit.implement` asks before
  running when any are unchecked; never tick them on the user's behalf.
- **Analyze** is read-only. Fix findings at the artifact that owns them (spec, plan or tasks), then
  re-run it until clean.
- **Implement** in stages: Setup + Foundational, then one user story per run, verifying between
  runs. A whole feature in one run overflows context and hides which task broke the build.
- **Converge** only appends tasks to `tasks.md`. Repeat implement → converge until it reports
  converged, then run the full gate yourself.

### 5. Review and ship

- Review code and `specs/NNN-*/` changes in the same PR; a plan that no longer matches the code is
  a bug in the PR.
- Decide once how specs age (immutable history per feature, or a living `spec.md`) and write it in
  the constitution's Governance section.
- GitHub issues from tasks: `specify extension add github`, then `/speckit.github.taskstoissues`
  (the core `taskstoissues` command is deprecated).

## RIGHT / WRONG

```text
WRONG  /speckit.specify Build an Orders screen with a ViewModel, Room cache and Ktor.
RIGHT  /speckit.specify Users see their orders, also offline with the last loaded list ...
       /speckit.plan   MVI ViewModel in :feature:orders, Room KMP cache in :core:data, Ktor ...
```
Why: the spec is checked for testable behaviour; stack choices in it skip the plan's
constitution check and research.

```markdown
<!-- WRONG: generated with core templates, web paths and no tests -->
- [ ] T012 [US1] Create OrderService in src/services/order_service.py

<!-- RIGHT: Gradle module + source set, test before code -->
- [ ] T012 [US1] Test cached orders when offline in feature/orders/src/commonTest/kotlin/com/example/app/orders/OrdersViewModelTest.kt
- [ ] T013 [US1] OrdersViewModel offline path in feature/orders/src/commonMain/kotlin/com/example/app/orders/OrdersViewModel.kt
```
Why: without the overrides and the Test-First principle the generator falls back to its defaults.

```text
WRONG  /speckit.implement            (whole feature, then "it builds")
RIGHT  /speckit.implement Now US1 only ...  → ./gradlew :feature:orders:allTests → /speckit.converge
```
Why: staged runs keep each failure attributable to one story.

## Scope guards

- Bug fixes do not need the SDD flow. Write a regression test (`android-tdd`); the optional `bug`
  extension (`specify extension add bug`) adds assess → fix → test commands if the team wants a
  record.
- To refresh a project after a CLI upgrade, prefer `specify integration upgrade <key>` over
  re-running `specify init`. It does not overwrite `.specify/memory/constitution.md` and stops on locally edited managed files
  unless `--force`.
- Community extensions and presets are not audited; read their source before `specify extension add`.

## Report format

```
Spec Kit <version> · integration <claude|codex> · feature specs/NNN-short-name
constitution check  PASS | n violations (justified in plan.md Complexity Tracking)
analyze             clean | n findings fixed in <artifact>
checklists          n/m reviewed by <person>
tasks               done x/y; converge passes: n (last: Converged)
gate                ./gradlew verify PASS | FAIL (<task>)
not covered         <manual device checks, iOS run, NOT_RUN items>
```

## Checklist

- [ ] Installed Spec Kit version and command spelling checked against the repo's files.
- [ ] Constitution built from the repo's real rules and includes Test-First.
- [ ] Plan and tasks overrides in `.specify/templates/overrides/` use modules and source sets.
- [ ] Spec has no stack words; clarify run until no `[NEEDS CLARIFICATION]` remains.
- [ ] Plan's Constitution Check passes or each violation is justified.
- [ ] Every story phase has test tasks before code; analyze is clean.
- [ ] Implemented per phase/story; converge reports converged; `./gradlew verify` passes.
- [ ] `specs/` changes reviewed in the same PR as the code.
